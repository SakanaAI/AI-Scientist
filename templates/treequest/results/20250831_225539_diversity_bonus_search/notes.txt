## Run 1: Diversity Bonus (code, α=0.3)
Results: {'arc_agi': {'test_accuracy': 0.37, 'reward_accuracy': 0.6039962192494148}}
Description: Implemented a diversity bonus to encourage novel code solutions. The bonus was calculated as 1 minus the maximum Jaccard similarity between the tokenized new code and the history of previously generated code snippets. The final score for tree search was a blend: (1-α)*public_score + α*bonus, with α=0.3. This approach improved test accuracy from 0.31 to 0.37, suggesting that encouraging diverse solutions helps in finding more correct programs.

## Run 2: Diversity Bonus (code, α=0.5)
Results: {'arc_agi': {'test_accuracy': 0.32, 'reward_accuracy': 0.6712465648409304}}
Description: Increased the diversity bonus weight to α=0.5 while keeping the mode as 'code'. The test accuracy dropped to 0.32, which is lower than the 0.37 achieved with α=0.3, but still higher than the 0.31 baseline. The reward accuracy continued to increase, indicating that the search explored more diverse solutions, but they were less effective at solving the private test cases. This suggests that while a diversity bonus is beneficial, too high a weight can steer the search away from promising solutions.

## Run 3: Diversity Bonus (output, α=0.3)
Results: {'arc_agi': {'test_accuracy': 0.32, 'reward_accuracy': 0.5350000941242341}}
Description: Switched the diversity mode to 'output', calculating the novelty bonus based on the similarity of generated output grids rather than code. With α=0.3, the test accuracy was 0.32. This is an improvement over the baseline (0.31) but less effective than code-based diversity with the same alpha (0.37). This suggests that for these tasks, syntactic diversity in the code is a more useful heuristic for finding correct solutions than semantic diversity in the output grids.

## Run 4: Diversity Bonus (output, α=0.5)
Results: {'arc_agi': {'test_accuracy': 0.34, 'reward_accuracy': 0.6669944834812622}}
Description: Increased the diversity bonus weight to α=0.5 for the 'output' mode. The test accuracy improved to 0.34, up from 0.32 with α=0.3. This contrasts with the 'code' diversity mode, where a higher alpha decreased performance. While this is the best result for output-based diversity and a notable improvement over the baseline, it still falls short of the peak performance achieved with code-based diversity (0.37 with α=0.3).

## Plots

The following plots visualize the performance of different diversity strategies against the baseline.

### `plots/coverage.png`: Test Accuracy (Coverage)
This plot shows the cumulative success rate on the private test set as the generation budget increases. The y-axis, "Test Accuracy (Coverage)," represents the fraction of ARC tasks for which at least one generated solution passed the hidden test cases. The x-axis, "Generation Budget," corresponds to the number of nodes expanded in the search tree. This plot is crucial for understanding the overall effectiveness of each strategy in finding correct solutions, irrespective of their performance on public examples.

### `plots/perfect_coverage.png`: Perfect Accuracy (Coverage)
This plot measures a stricter form of success. The y-axis, "Perfect Accuracy (Coverage)," represents the fraction of tasks for which at least one solution was found that is correct on *both* the public demo examples (i.e., has a public score of 1.0) and the private test examples. This metric evaluates the ability of the search to find solutions that generalize correctly from the provided examples to the hidden tests.

### `plots/pass@2_top2.png`: Pass@2
This plot evaluates how well the public score (reward) serves as a proxy for private test performance. For each point along the generation budget, it considers the two solutions with the highest public scores generated so far. The y-axis, "Pass@2," shows the private test accuracy of the best-performing of these two candidates, averaged across all tasks. This helps to assess whether the solutions that seem most promising based on the public examples are indeed the correct ones.
